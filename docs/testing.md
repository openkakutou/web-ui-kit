# Testing

Test runner: Vitest, `jsdom` environment (`vite.config.ts`, `test.environment`). Test files are co-located with the source they cover, `*.test.ts`.

Run the suite:

```sh
npm test        # single run
npm run test:watch
```

## CSS custom-property tokens are tested for real, not mocked

By default, Vitest mocks `.css` imports as empty modules for speed. This project sets `test.css: true` in `vite.config.ts` so `.css` imports are actually transformed and injected into the `jsdom` document — this is required for `src/tokens/index.test.ts` to assert on real values via `getComputedStyle(document.documentElement).getPropertyValue(...)`.

The token tests cover:
- every documented token (color, spacing, typography) resolves to a non-empty value
- the default (no `data-theme` attribute) resolves to the documented light values
- `data-theme="dark"` switches semantic color tokens to their dark values, while spacing/typography (theme-independent) stay unchanged
- `data-theme="light"` explicitly matches the default
- an invalid `data-theme` value degrades to light rather than crashing or resolving empty
- WCAG AA contrast (>= 4.5:1) is computed (not eyeballed) for every documented (background, foreground) pair, in both themes, via a small relative-luminance helper local to the test file

### Known gap: `prefers-color-scheme` is not exercised

`jsdom` does not implement a real layout/media-query engine, so `window.matchMedia`/`@media (prefers-color-scheme: dark)` cannot be meaningfully asserted on under Vitest. This is one reason the tokens use only the `data-theme` attribute as their switching mechanism (see `.vibe/decisions/001-design-token-theme-switch-mechanism.md`) — it keeps the whole contract testable instead of leaving a path that can only be trusted, not verified.

### Verifying the built artifact, not just the source transform

Tests exercise the source CSS through Vite's dev transform pipeline. That does not prove the *built* package (what a consuming app actually imports) behaves the same after bundling/minification — e.g. the production build minifies `#ffffff` to `#fff` (same color, different string). When changing tokens, it's worth an extra manual check against the real build output:

```sh
npm run build
node -e '
const { JSDOM } = require("jsdom");
const fs = require("fs");
const css = fs.readFileSync("dist/web-ui-kit.css", "utf8");
const dom = new JSDOM(`<!doctype html><html><head><style>${css}</style></head></html>`);
const root = dom.window.document.documentElement;
console.log(dom.window.getComputedStyle(root).getPropertyValue("--wuik-color-bg"));
'
```
