# Module: i18n
**Role:** The shared localization layer: `initI18n` builds one i18next instance per consuming app, merging that app's own locale catalog with `web-ui-kit`'s own (shortcuts panel, slider/color-picker invalid-state text) under separate namespaces so neither collides. `t()` is what every standalone component in this kit actually calls to render its own text, falling back to a given English default when no app has set up i18n at all. `<wuik-locale-switcher>` is the shared UI that lists and switches locales.
**Files:** `src/i18n/i18n.ts`, `src/i18n/i18n-resources.ts`, `src/i18n/locale-names.ts`, `src/i18n/locale-switcher.ts`, `src/i18n/locales/en.json`, `src/i18n/locales/fr.json`, `src/i18n/index.ts`
**Exports:** `initI18n` (async, returns a real `i18next` instance), `t`, `getI18n`, `onLocaleChange`, `getSupportedLocales`, `localeDisplayName`, `WuikLocaleSwitcherElement` (`<wuik-locale-switcher>`), `WUIK_NAMESPACE`/`DEFAULT_LOCALE`/`DEFAULT_STORAGE_KEY` (constants), `InitI18nOptions`/`LocaleCatalog`/`LocaleCatalogs` (types)
**Public contract:** See `docs/api.md` for the full API and `.vibe/decisions/013-i18n-integration-layer-architecture.md` for the design rationale. Depends on `i18next` + `i18next-browser-languagedetector` (real runtime dependencies, bundled into `dist/web-ui-kit.js` — nothing extra for a consuming app to install). Locale resolution order: a persisted `localStorage` override, then the browser's own language, falling back to `DEFAULT_LOCALE` ("en"). Every text-bearing standalone component subscribes to `onLocaleChange` (a bus decoupled from any one i18next instance's identity, since a component may mount before `initI18n` is ever called) rather than importing an instance directly; `<wuik-locale-switcher>` instead holds a direct instance reference (via its `.i18n` property, same pattern as `<wuik-shortcuts-panel>.manager`) since it is always wired to one explicitly.
**Depends on:** `modules/tokens.md`
