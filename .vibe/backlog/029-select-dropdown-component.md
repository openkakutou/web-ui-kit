# Select / dropdown component

## Description
Apps fall back to native <select> because the kit offers no styled equivalent (see item 012's under-adoption finding). Add <wuik-select> with keyboard operation, label forwarding, invalid state and token styling, consistent with the other form components.

## Acceptance Criteria
- [ ] Single-choice select with arrow/Home/End/type-ahead keyboard support
- [ ] label, disabled and is-invalid states follow the shared form conventions (decision 007)
- [ ] Axe-style accessibility baseline and visual-regression snapshot added
- [ ] Documented in docs/ with an example
